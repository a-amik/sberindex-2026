# Прогноз потребления в муниципалитетах и раннее обнаружение шоков

Решение для онлайн-конкурса СберИндекса 2026, номинация «Прогнозирование».
Безналичные потребительские расходы на жителя в 2 190 муниципальных
образованиях, шесть категорий трат, январь 2023 — декабрь 2024.

Решение состоит из трёх частей, которые работают каждый месяц на данных,
известных к его концу:

- **прогноз** на 1, 3, 6 и 12 месяцев: ряд МО раскладывается на общий фактор
  группы «категория × тип поселения» и собственное отклонение МО; ансамбль
  двух моделей на панели, LightGBM и Chronos-2, поверх — поправки по внешним сигналам
  и конформные интервалы;
- **обнаружение точек изменений**: семь онлайн-детекторов на отклонении МО
  от фактора, согласие интервала Chronos-2 и z-оценки как список на проверку;
- **новости и события**: заголовки федеральных лент и телеграм-каналы органов
  власти, привязанные к МО и субъектам, — для датировки и объяснения шоков.

`web/public/data/meta.json`.

## Запуск

Нужен Python 3.12 и `bsdtar` (есть в macOS и в большинстве дистрибутивов Linux).

```bash
make setup     # окружение .venv и зависимости
make data      # загрузка из первоисточников (~15 мин, больше всего — погода)
make dataset   # панель, характеристики МО, соседи, внешние ряды, проверки
make forecast  # бэктест: эталоны, Prophet, панель, LightGBM, Chronos-2, Chronos-Bolt
make grid      # чувствительность Prophet к настройкам
make ensemble  # ансамбль: выбор по целям до мая 2024 года
make signals   # внешние сигналы, строгий итог → results/forecasts/ensemble_strict.parquet
make ahead     # прогноз вперёд 2025—2027 от декабря 2024 → results/forecasts_forward/ensemble_strict.parquet
make cpd       # детекторы точек изменений: полусинтетика и реальные данные
make cases     # реальные кейсы и раннее предупреждение
make news      # заголовки лент, разметка, согласование и проверки
make shocks    # телеграм-каналы и предсказание шоков
```

`make site` пересобирает данные сервиса (`web/public/data`). Три его слоя —
отраслевые доли МО, профиль людей и проверка на 2025 годе — строятся из
данных, снятых руками: плоской выгрузки БД ПМО «Если быть точным» (CC BY 4.0,
читается по диапазонам байтов, `tools/remote_zip.py`, шаги 37, 41a—41c),
формы Росстата (с октября 2026 года по старому адресу недоступна, шаг 23) и
реестра событий 2025—2026 годов (`configs/events_2025_2026.json`, с источниками).
Без этих входов `make site` оставляет закоммиченные файлы слоёв.
Версии библиотек закреплены: `requirements.txt` — прямые зависимости,
`requirements-lock.txt` — полный слепок, его ставит `make setup`.

`make all` выполняет всё по порядку. Сдаваемая модель — строгий прогноз
(`ensemble_strict`): ансамбль-медиана четырёх моделей с поправкой роста
фактора на шагах 4—12 и конформными интервалами; данные сервиса считаются
с него. Разметка режимов ЧС (`make shocks`, `39_chs_markup.py`) без сканов
актов pravo.gov.ru берётся из сохранённой копии
`results/signal_value/chs_events.json`; скачать акты заново —
`39_chs_fetch.py` (macOS, OCR). Возрастная активность СберИндекса входит
в `make data` (`sberindex_datasets` в `configs/default.yaml`). Фундаментальные модели скачивают веса
с Hugging Face (amazon/chronos-2, amazon/chronos-bolt-base) и считаются
несколько часов на CPU или Apple Silicon.

Сервис: `docker compose up --build` → http://localhost:8080/ (порт меняется
переменной `PORT`). Данные экрана готовит `web/scripts/export_data.py`.

Отдельный источник: `.venv/bin/python scripts/01_download.py --only rosstat`.
Любой параметр конфигурации меняется без правки файла:
`--set panel.neighbours_k=12`.

Сырые файлы в репозиторий не входят. `data/manifest.json` хранит адрес,
размер, sha256 и дату загрузки каждого файла.

Сайты Сбера, СберИндекса и Росстата подписаны сертификатами НУЦ Минцифры,
и sberindex.ru не отдаёт промежуточный сертификат. Проверка TLS не
выключается: публичные корневой и промежуточные сертификаты лежат в `certs/`,
загрузчик собирает из них и certifi общий bundle.

## Что получается

`data/processed/`:

| Файл | Содержимое |
|---|---|
| `panel.parquet` | МО × категория × месяц, признак полного ряда |
| `mo.parquet` | характеристики МО: субъект, тип, статус, координаты, население, доля городского, доступность рынков, моногород |
| `neighbours.parquet` | 8 ближайших МО по автодороге; для 18 МО без дорог — по расстоянию между центрами |
| `regions.parquet` | МО, свёрнутые в субъект с весом по населению, и число МО в свёртке |
| `national.parquet` | общероссийские ряды, ставка, календарь |
| `regional.parquet` | субъект × месяц: ИПЦ по группам, зарплата, туризм |
| `checks.json` | результаты проверок данных |

## Проверки данных

`make dataset` печатает и сохраняет:

- состав набора по месяцам и типы неполных рядов (поздний старт, ранний конец, дыры);
- эффект состава: медиана по всем МО месяца против медианы по МО с полным рядом;
- долю прочих трат — «Все категории» за вычетом пяти категорий — и её скачки;
- выбросы относительно медианы своего ряда в единицах MAD;
- покрытие населением, соседями и региональными рядами;
- сверку прироста год к году по панели с общероссийским рядом СберИндекса;
- сдвиг апреля 2023 года по типам МО.

## Протокол сравнения прогнозов

- **Скользящая точка прогноза** T от декабря 2023 до ноября 2024, окно
  расширяется. Модель видит ряд по T включительно и прогнозирует шаги
  1…min(12, декабрь 2024 − T).
- **Горизонт H** — средняя ошибка по шагам 1…H в тех точках, где окно T+H
  целиком в данных. Для H = 12 такая точка одна — декабрь 2023 года.
- **Ряды** — 12 096 рядов «МО × категория» с полной историей.
- **Метрики.** MAE в рублях на жителя — главная. R² по уровням близок
  к единице у любой модели из-за разброса уровней между МО, поэтому рядом
  стоит R² прироста — доля дисперсии лог-изменения от точки прогноза,
  которую модель объясняет.
- **Сравнение с базовой моделью** — на одних и тех же парах «ряд × точка ×
  шаг»: критерий Уилкоксона по рядам (ошибка усредняется внутри ряда), доля
  рядов, где модель точнее, и блочный бутстрап по целевым месяцам.
- **Честный выбор.** Состав ансамбля и силы внешних поправок выбираются
  по парам, цель которых не позже мая 2024 года; отчётное окно — точки
  с июня 2024 года, и ни одна его цель при выборе не используется.
  Исключение одно и названо: Chronos-2 включён в ансамбль обязательным
  членом (`force_include`) после просмотра отчётного окна; свободный отбор
  сохранён в `results/metrics/ensemble_selection_free.csv`.
- **Базовая модель — Prophet в двух редакциях.** `prophet_default` — Prophet
  как есть: на истории короче двух лет он сам выключает годовую сезонность.
  `prophet_yearly3_mult` — с годовой сезонностью третьего порядка,
  мультипликативной. Десять настроек сравниваются на выборке из 1 200 рядов
  (`make grid`), чтобы выигрыш нельзя было списать на неудачную настройку базы.

Таблицы: `results/metrics/forecast_by_horizon.csv`, `…_by_category.csv`,
`…_vs_prophet_default.csv`, `prophet_grid_*.csv`.

## Эксперимент с региональными сигналами

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/09_regional_signals.py --probe
.venv/bin/python scripts/09_regional_signals.py
.venv/bin/python scripts/09_regional_signals.py --config configs/regional_signals_chronos.yaml --output results/regional_signals_chronos
```

Протоколы — `docs/regional_signals_protocol.md` и
`docs/regional_signals_chronos_protocol.md`. Общая поправка субъекта
учится известным ошибкам базового прогноза; цены, зарплата, погода,
календарь и новости проверяются отдельными группами. Данные после
точки прогноза не входят в признаки и обучающие цели. Архивы исторических
версий внешних рядов отсутствуют, поэтому доступность проверяется
лагами и остаётся допущением.

Результаты лежат в `results/regional_signals/` и
`results/regional_signals_chronos/`: метрики муниципальных и региональных
расходов, разрезы, выбор на раннем окне, аудит обучения, хеши данных
и снимки исходников. Действующие прогнозы в `results/forecasts/`
эксперимент не перезаписывает. Интервалы базовой модели к новой поправке
не переносятся: сохранённый прогноз содержит только новую оценку точки.

## Короткие горизонты, поиск и анонсы

```bash
.venv/bin/python scripts/regional_horizon_calibration.py
node scripts/collect_wordstat_pilot.cjs
.venv/bin/python scripts/regional_prospective_experiment.py
.venv/bin/python scripts/regional_prospective_slices.py
```

Первый запуск использует сохранённые поправки, выбирает отдельно шаг 1
и шаги 2–3 по региональной MAE с ограничением на муниципальную ошибку.
На шагах 4–12 поправка отключена. Протокол:
`docs/regional_horizon_calibration.md`.

Wordstat читается собственной фоновой вкладкой существующего браузера
на 9222. Нужны Chrome, запущенный с `--remote-debugging-port=9222`, вход
в Яндекс в нём и пакет `playwright` (`npm install playwright`). Данные
входа не сохраняются. Сборщик
останавливается при ограничении сервиса; готовые ответы берёт из кэша.
Пять субъектов и Россия, пять запросов, 36 месяцев; параметры и RAW
в `data/external/wordstat/`. Справочник анонсов и официальные снимки —
`data/external/announced_events/`. Протокол:
`docs/regional_prospective_signals.md`.

Все эти опыты исследовательские: позднее окно уже просмотрено, новый
независимый тест не появился. Поиск измерен регионально только в пяти
субъектах; остальные получают национальный сигнал. Два анонса не дают
надёжной оценки эффекта индексаций. Данные и код остаются локально,
сохранённые базовые прогнозы не перезаписываются.

## Проверка задержек макроданных

```bash
.venv/bin/python scripts/audit_macro_releases.py
.venv/bin/python scripts/regional_macro_robust.py
```

Реестр публикаций задан в `configs/release_audit.json`. Сборщик сохраняет
PDF/HTML, извлекает четыре ИПЦ и зарплату, сравнивает с нынешней таблицей
с учётом округления. Проверенные семь релизов не сертифицируют всю панель.

Опыт `docs/regional_macro_robust.md` разделяет цены, номинальную зарплату
и ставку, проверяет две политики задержки и выбирает короткие шаги
по худшей ошибке раннего окна с ограничением муниципальной ошибки.
Результаты и аудит — в `results/regional_macro_robust/`; сверка публикаций —
в `results/macro_release_audit/`. Основной прогноз не перезаписывается.
